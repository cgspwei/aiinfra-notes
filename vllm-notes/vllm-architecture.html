vLLM 架构总览

从 HTTP 请求到 GPU 核函数的完整链路

sourcevllm-project/vllm @ main

vLLM 的架构分四层：入口层、引擎编排层、引擎核心层、执行与模型层。V1 把调度放进独立进程，把前向计算放进每卡一个的 Worker 进程。本文按数据流从上往下拆。

A

设计目标

vLLM 用三件事换吞吐：连续批处理、分页 KV cache、多进程解耦。

目标 手段
高吞吐 连续批处理、PagedAttention、前缀缓存
低延迟 Chunked prefill、CUDA Graph、投机解码
横向扩展 TP / PP / DP / EP、分离式服务
可插拔 平台、注意力后端、模型、LoRA
核心取舍

CPU 只决定"这一步算什么"，GPU 只负责算。两者之间传 token 索引，不传完整请求。

B

分层总览

控制面自上而下。入口层不碰 GPU，Worker 不碰 HTTP。

C

进程架构

V1 按职责切进程。每个进程只做一类事。

进程 数量 职责
API Server A，默认等于 DP HTTP、分词、多模态加载、流式返回
Engine Core DP 调度、KV cache、组织每步 batch
GPU Worker N = DP × PP × TP 加载权重、执行前向、管理显存
DP Coordinator DP > 1 时 1 个 跨 DP 负载均衡、MoE 同步前向
算进程数

单机 TP=4：1 个 API Server + 1 个 Engine Core + 4 个 GPU Worker，共 6 个进程。 TP=2、DP=4、8 卡：4 + 4 + 8 + 1，共 17 个进程。

API Server 与 Engine Core 是多对多 ZMQ。Engine Core 与 Worker 之间走共享内存消息队列。SchedulerOutput 广播给所有 Worker，Worker 回传 ModelRunnerOutput。

D

调度器

调度器在 Engine Core 进程内。它是 token 预算制：每步把 max_num_batched_tokens 填满。

没有独立的 prefill 阶段和 decode 阶段。每个请求记录已算 token 数，调度器补差额。一个循环同时覆盖 chunked prefill、前缀缓存和投机解码。

能力 机制 默认
连续批处理 每步按 token 预算组批 开
Chunked prefill 长 prompt 拆到多步 开
前缀缓存 block hash 命中即复用 开
抢占 释放 KV，回到等待队列重算 自动
异步调度 CPU 调度与 GPU 执行重叠 开，部分配置回退

两种策略：FCFS（默认）和 priority。KV 不足时，调度器抢占运行中的请求。被抢占的请求丢弃 KV，重新排队，之后从头重算。前缀缓存能恢复一部分进度。

E

KV cache 管理

KV cache 按固定大小的 block 管理，默认 16 个 token 一块。BlockPool 持有全部 block 和空闲队列。KVCacheManager 按请求分配和释放。

前缀缓存的核心是 block hash 链。一个 block 的 hash 由父 block hash 和本块 token 决定。相同前缀的请求自然命中同一批 block。

vLLM 支持多种 KV cache 组：全注意力、滑动窗口、Mamba 状态、交叉注意力。每组的大小和布局可以不同。多模态请求另有 encoder cache，按 encoder 输出块管理。

结构 作用
BlockPool 持有 block、空闲队列、hash 到 block 的映射
KVCacheManager 请求级分配、释放、前缀查询
KVCacheCoordinator 协调多组 KV cache
KV Connector 跨实例搬运 KV，用于分离式部署
F

执行层

Executor 是 Engine Core 和 Worker 之间的边界。它把一次调度结果广播给所有 Worker，再收集结果。

后端 适用场景
UniProcExecutor 单进程，调试和单卡
MultiprocExecutor 默认，同机多进程
RayExecutorV2 多机或已有 Ray 集群
external_launcher torchrun 等外部拉起

每个 GPU 一个 Worker 进程。Worker 启动时做四件事：加载权重、测显存、按 profile 结果分配 KV cache、捕获 CUDA Graph。

Worker 里是 ModelRunner。它维护请求状态，准备输入张量，调用模型前向，采样下一个 token。关键方法是 _update_states、_prepare_inputs、execute_model、capture_model。

G

模型与算子

模型层由注册表驱动。vLLM 把 Hugging Face 的 architecture 名映射到模型类。所有模型使用统一构造签名：

def __init__(self, *, vllm_config: VllmConfig, prefix: str = "")

这样 ModelRunner 不需要知道具体模型类型。视觉语言模型也按同样方式组合视觉塔和语言模型。

层内使用并行线性层。TP 把权重按头或通道切开。量化层替换 Linear，支持 FP8、NVFP4、INT4 等格式。

注意力后端在启动时按模型和硬件选择：

后端 典型场景
FlashAttention NVIDIA / AMD 通用
FlashInfer 低延迟 decode
FlashMLA DeepSeek 类 MLA 模型
Triton 跨平台兜底
Mamba / GDN 状态空间与线性注意力
ROCm AITER AMD 专用

底层算子在 csrc/ 里用 CUDA/HIP 编写，另有 CUTLASS、Triton 和 CuTeDSL 实现。

H

编译与 CUDA Graph

vLLM 用 torch.compile 做图级优化，再用 CUDA Graph 消除启动开销。两者结合成 piecewise 方案：图按 shape 分桶，decode 用完整 CUDA Graph，prefill 用分段图。

编译结果按 batch 大小缓存。启动时用 _dummy_run 预热并捕获常见 shape。运行中遇到新 shape 就回退到 eager。

I

一次请求的旅程

请求结束时，调度器释放 KV block。block 留在池里供后续请求命中，直到被驱逐。

J

并行与加速子系统

并行方式 切分对象 主要目的
TP 权重按头或通道 单机多卡降延迟
PP 按层切分 跨机放超大模型
DP 复制完整模型 提高总吞吐
EP MoE 专家 让专家分布到多卡

投机解码由调度器和 Worker 配合。草稿模型或 n-gram 先给出候选 token，主模型一次验证。仓库里有 EAGLE、DFlash、n-gram、suffix 等实现。

结构化输出用 grammar 约束。调度器计算 bitmask，采样时屏蔽非法 token。

分离式服务把 prefill、decode、encode 拆到不同实例。KV Connector 负责跨实例搬运 KV cache。
